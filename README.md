# FreeDoom

Контроль качества диалогов RU / KZ / EN: оценка Gemini, объяснения с привязкой к репликам, аудиоплеер, апелляции и редактор чек-листа.

## Запуск

Python 3.11+, один процесс:

```sh
python -m pip install -r requirements.txt
python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Введите ключ Gemini в шапке сайта. Используется строго `gemini-3.5-flash-lite`. Ключ сохраняется в localStorage браузера под `gemini_api_key` и восстанавливается при перезагрузке. Очистка поля очищает сохранённое значение. На сервере ключ используется только для текущего запуска и не попадает в JSON.

## Работа

1. Выберите DEV/PROD и загрузите JSON. Поддерживаются `data.records`, `records` и массив диалогов. Для GET организаторов укажите `organizer_api_url` в локальном `data/config.json` (ссылка из кнопки на стр. 3 гайда); загрузка файла настройки не требует.
2. При необходимости измените чек-лист: названия, правила, веса, допустимые значения и флаги.
3. «Оценить все» запускает фоновую оценку. Прогресс и готовые карточки обновляются каждые 1,5 секунды. Перезагрузка страницы не останавливает задачу. Сервер должен продолжать работать.
4. Нажмите номер реплики для перехода к ней с подсветкой на 2 секунды. Если задан `audio_url`, доступен плеер; время реплики в формате MM:SS или HH:MM:SS используется для перехода в записи после загрузки метаданных.
5. В режиме «Оператор» нажмите «Оспорить» у критерия и отправьте комментарий. В центре апелляций доступны фильтры ожидающих и рассмотренных обращений.
6. В режиме «Супервизор» откройте центр апелляций: проверьте цитаты, выберите новое значение (или подтвердите прежнее), укажите причину и нажмите «Утвердить». Итог пересчитывается сразу по чек-листу, использованному при оценке.
7. Скачайте results.json после обработки всех диалогов. Проверьте ошибки и количество записей: DEV — 65, PROD — 10. Экспорт сохраняет формат результатов, история пересмотров хранится отдельно в состоянии.

Роли — переключатель интерфейса без авторизации, как предусмотрено для демонстрации. Это не разграничение доступа к API.

## Расчёт и история

Итог = 100 × сумма набранных взвешенных баллов / сумма применимых весов. N/A исключается из знаменателя. Флаги нарушений имеют вес 0 и не обнуляют итог. В `original_ai` неизменно сохраняются исходные ответы, объяснения и балл ИИ. Каждая апелляция сохраняет исходную и предыдущую оценку, комментарий, решение, причину, время и итог после пересмотра. Повторная оценка и новый импорт архивируют прежний набор и историю в `archives`.

## Хранение

- `data/state.json` — диалоги, оценки, апелляции, архивы; восстанавливается при запуске.
- `data/checklist.json` — текущий чек-лист.
- `data/dev_source.json`, `data/prod_source.json` — исходные наборы.
- `results/dev/results.json`, `results/prod/results.json` — результаты для сдачи.

Один server.py и один static/index.html. Без базы данных, .env, внешней очереди или Render. Только память процесса и локальные JSON. Не запускайте несколько workers: состояние общее только внутри одного процесса. При остановке процесса фоновая оценка прерывается; уже готовые результаты сохранены, незавершённый запуск нужно повторить.

## API

- `POST /api/load-data`: JSON `{ "group_id": "DEV", "dataset": [...] }` либо multipart `file`, `group_id`.
- `GET /api/dialogues`: диалоги, результаты, прогресс, апелляции, чек-лист запуска и экспорт.
- `POST /api/evaluate` (также `/api/evaluate-batch`): `{ "api_key": "..." }`; немедленно возвращает `{ "status": "started" }`. Обработка через FastAPI BackgroundTasks.
- `POST /api/checklist`: `{}` читает; `{ "checklist": [...] }` сохраняет.
- `POST /api/appeal`: `conversation_id`, `criterion_id`, `comment`.
- `POST /api/appeal/resolve`: `conversation_id`, `criterion_id`, `new_value`, `reason`.

## Проверка

Проверены возврат HTTP-ответа до завершения фоновой задачи, запрет параллельного запуска, прогресс, отправка и разрешение апелляции, запрет дубликатов, типы оценок, пересчёт с N/A, сохранение исходной оценки и истории на диск, архивирование и отсутствие ключа в состоянии/экспорте. Реальный запрос к Gemini требует рабочего ключа и доступа к указанной модели; точность на DEV пока не измерена.

## API организаторов и контрольный набор

Адрес API хранится в `data/config.json`, который исключён из Git вместе с `data/`. Поле «group_id API» позволяет указать выданный организаторами идентификатор; если оно пустое, используется DEV или PROD. Выбор набора определяет папку выгрузки: `results/dev/results.json` или `results/prod/results.json`. Контрольный идентификатор не следует угадывать: его сообщают организаторы.

Модель: Gemini 3.5 Flash-Lite (external_api). Тариф предыдущей модели к ней не применяется; стоимость зависит от актуального тарифа и использованных токенов.

## Скорость и лимиты

Один вызов generateContent на диалог за запуск, все критерии текущего чек-листа (по умолчанию 8) в одном запросе. Автоматических повторов нет, включая 429 и невалидный JSON. Ошибки можно повторить отдельным запуском через интерфейс.

Один общий httpx.AsyncClient, await client.post, asyncio.gather и asyncio.Semaphore(5). Thinking minimal, maxOutputTokens 1200. Обоснование: одно законченное предложение с конкретной причиной, обычно 8–18 слов. Обрезанный ответ помечается ошибкой, оценки не придумываются.

Общий ограничитель: 14 запросов/мин и консервативный бюджет 2000000 входных токенов/мин (по UTF-8 байтам). При 429 очередь ждёт Retry-After / retryDelay и backoff с jitter; известная квота учитывается с запасом, неизвестная снижает частоту. Это локальные настройки, а не известная квота аккаунта. «Продолжить / повторить ошибки» сохраняет успешные оценки, если модель и чек-лист не менялись. При смене модели требуется полная оценка, чтобы экспорт правильно указывал использованную модель.

## Проверка качества и диагностика

Промпт получает исходный номер первой реплики человека-оператора; слова клиента, бота и системы не приписываются ему. Применимость N/A проверяется до оценки действия. Для изменённого чек-листа приоритет имеют его правила.

Gemini возвращает компактный объект по responseJsonSchema: ID критериев обязательны, значения типизированы, ссылки ограничены длиной транскрипта. Поля v/r/e разворачиваются сервером в стандартные value/rationale/evidence_turns. Схема выгрузки JSON 1.0 не меняется. Лимит ответа 1200 токенов и один запрос сохраняются.

В data/diagnostics сохраняются отдельные JSON: HTTP-статус, этап ошибки, тип исключения, finishReason, usageMetadata, время и ответ модели (до 24000 символов). Ключ и заголовки запроса не сохраняются; точное совпадение ключа в ответе скрывается. Эти файлы могут содержать фрагменты диалогов и исключены из Git вместе с data/.

Раскройте «Проверка нескольких диалогов без изменения выгрузки», укажите 1–10 ID через запятую и запустите проверку. Результаты находятся в data/verification.json и не заменяют результаты для сдачи. Это настоящие обращения к Gemini, использующие ключ из поля страницы. После изменения версии промпта продолжение старой оценки запрещено: нужна полная переоценка.

## Остановка и измерение времени

«Остановить оценку» отменяет ожидающие и активные HTTP-запросы, сохраняет готовые результаты. Уже отправленный запрос может учитываться провайдером даже после отмены. «Продолжить» обрабатывает недостающие и ошибочные диалоги. Таймер показывает всё время запуска, включая очередь и паузы API. Итог сохраняется в data/runs/*.json и state.last_run. При продолжении отдельно фиксируется количество обработанных за этот запуск.

Один запрос содержит один диалог. Между стартами выдерживается 60/14 + 0.02 секунды (примерно 4.306 секунды); одновременно в обработке не более пяти задач. Скользящее минутное окно учитывает общий RPM. На реальном тесте провайдер сообщил для текущего проекта Free Tier квоту 15 RPM. Квота провайдера сохранена в data/config.json:model_rate_limits. Рабочий предел — 14 RPM с запасом; автоматически уточняется по структурированному QuotaFailure. История резервирования запросов и пауз сохраняется в data/rate_history.json и восстанавливается после перезапуска. С такой квотой 65 отдельных запросов не могут завершиться за 40–50 секунд. Плановая длительность с плавной очередью — около 4.5–5 минут, если нет внешних ошибок и запросов из других приложений того же проекта. Увеличивать число параллельных задач сверх пяти или скрывать паузы в таймере бессмысленно.
