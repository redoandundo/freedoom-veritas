# FreeDoom

Контроль качества диалогов RU / KZ / EN: оценка Gemini, объяснения с привязкой к репликам, аудиоплеер, апелляции и редактор чек-листа.

## Запуск

Python 3.11+, один процесс:

```sh
python -m pip install -r requirements.txt
python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Введите ключ Gemini в шапке сайта. Используется строго `gemini-3.5-flash-lite`. Ключ сохраняется в localStorage браузера под `gemini_api_key` и восстанавливается при перезагрузке. Очистка поля очищает сохранённое значение. На сервере ключ используется только для текущего запуска и не попадает в JSON.

## Работа

1. Выберите DEV/PROD и загрузите JSON. Поддерживаются `data.records`, `records` и массив диалогов. Для GET организаторов укажите `organizer_api_url` в локальном `data/config.json` (ссылка из кнопки на стр. 3 гайда); загрузка файла настройки не требует.
2. При необходимости измените чек-лист: названия, правила, веса, допустимые значения и флаги.
3. «Оценить все» запускает фоновую оценку. Прогресс и готовые карточки обновляются каждые 1,5 секунды. Перезагрузка страницы не останавливает задачу. Сервер должен продолжать работать.
4. Нажмите номер реплики для перехода к ней с подсветкой на 2 секунды. Если задан `audio_url`, доступен плеер; время реплики MM:SS / HH:MM:SS или ISO 8601 используется для перехода в записи. ISO-время переводится в секунды относительно события начала записи (если оно отсутствует — первой временной метки), с вычитанием явно отмеченных пауз записи. Для событий до начала или внутри паузы переход в аудио недоступен. Кнопка времени у каждой реплики и ссылки из оценки запускают запись с выбранного места, в том числе при клике до загрузки метаданных.
5. В режиме «Оператор» нажмите «Оспорить» у критерия и отправьте комментарий. В центре апелляций доступны фильтры ожидающих и рассмотренных обращений.
6. В режиме «Супервизор» откройте центр апелляций: проверьте цитаты, выберите новое значение (или подтвердите прежнее), укажите причину и нажмите «Утвердить». Итог пересчитывается сразу по чек-листу, использованному при оценке.
7. Скачайте results.json после обработки всех диалогов. Проверьте ошибки и количество записей: DEV — 65, PROD — 10. Экспорт сохраняет формат результатов, история пересмотров хранится отдельно в состоянии.

Роли — переключатель интерфейса без авторизации, как предусмотрено для демонстрации. Это не разграничение доступа к API.

## Расчёт и история

Итог = 100 × сумма набранных взвешенных баллов / сумма применимых весов. N/A исключается из знаменателя. Флаги нарушений имеют вес 0 и не обнуляют итог. В `original_ai` неизменно сохраняются исходные ответы, объяснения и балл ИИ. Каждая апелляция сохраняет исходную и предыдущую оценку, комментарий, решение, причину, время и итог после пересмотра. Повторная оценка и новый импорт архивируют прежний набор и историю в `archives`.

## Хранение

- `data/state.json` — диалоги, оценки, апелляции, архивы; восстанавливается при запуске.
- `data/checklist.json` — текущий чек-лист.
- `data/dev_source.json`, `data/prod_source.json` — исходные наборы.
- `results/dev/results.json`, `results/prod/results.json` — результаты для сдачи.

Один server.py и один static/index.html. Без базы данных, .env, внешней очереди или Render. Только память процесса и локальные JSON. Не запускайте несколько workers: состояние общее только внутри одного процесса. При остановке процесса фоновая оценка прерывается; уже готовые результаты сохранены, незавершённый запуск нужно повторить.

## API

- `POST /api/load-data`: JSON `{ "group_id": "DEV", "dataset": [...] }` либо multipart `file`, `group_id`.
- `GET /api/dialogues`: диалоги, результаты, прогресс, апелляции, чек-лист запуска и экспорт.
- `POST /api/evaluate` (также `/api/evaluate-batch`): `{ "api_key": "..." }`; немедленно возвращает `{ "status": "started" }`. Обработка через asyncio.create_task и общий ограничитель частоты.
- `POST /api/evaluate` с `conversation_id`: переоценка одного выбранного диалога, обновляет карточку и сдаваемые результаты. Прежний результат и апелляции копируются в `single_history`; при смене чек-листа/модели сначала нужна полная оценка. Смешанные версии промпта помечаются, кнопка экспорта недоступна до обновления всех результатов.
- `POST /api/checklist`: `{}` читает; `{ "checklist": [...] }` сохраняет.
- `POST /api/appeal`: `conversation_id`, `criterion_id`, `comment`.
- `POST /api/appeal/resolve`: `conversation_id`, `criterion_id`, `new_value`, `reason`.

## Проверка

Проверены возврат HTTP-ответа до завершения фоновой задачи, запрет параллельного запуска, прогресс, отправка и разрешение апелляции, запрет дубликатов, типы оценок, пересчёт с N/A, сохранение исходной оценки и истории на диск, архивирование и отсутствие ключа в состоянии/экспорте. Реальный запрос к Gemini требует рабочего ключа и доступа к указанной модели; точность на DEV пока не измерена.

## API организаторов и контрольный набор

Адрес API хранится в `data/config.json`, который исключён из Git вместе с `data/`. Поле «group_id API» позволяет указать выданный организаторами идентификатор; если оно пустое, используется DEV или PROD. Выбор набора определяет папку выгрузки: `results/dev/results.json` или `results/prod/results.json`. Контрольный идентификатор не следует угадывать: его сообщают организаторы.

Модель: Gemini 3.5 Flash-Lite (external_api). Тариф предыдущей модели к ней не применяется; стоимость зависит от актуального тарифа и использованных токенов.

## Скорость и лимиты

Один диалог и все критерии в одном запросе generateContent, все критерии текущего чек-листа (по умолчанию 8) в одном запросе. Для временных сетевых сбоев и HTTP 502/503/504 включены максимум две повторные попытки; каждый повтор проходит общий RPM-лимитер. 401/403, квоты и невалидный JSON автоматически не повторяются. Ошибки можно повторить отдельным запуском через интерфейс.

Один общий httpx.AsyncClient, await client.post, asyncio.gather и asyncio.Semaphore(5). Thinking low, maxOutputTokens 16384 (общий бюджет рассуждения и ответа). Обоснование: одно законченное предложение с конкретной причиной, обычно 8–18 слов. Обрезанный ответ помечается ошибкой, оценки не придумываются.

Общий ограничитель: 14 запросов/мин и консервативный бюджет 2000000 входных токенов/мин (по UTF-8 байтам). При 429 очередь ждёт Retry-After / retryDelay и backoff с jitter; известная квота учитывается с запасом, неизвестная снижает частоту. Это локальные настройки, а не известная квота аккаунта. «Продолжить / повторить ошибки» сохраняет успешные оценки, если модель и чек-лист не менялись. При смене модели требуется полная оценка, чтобы экспорт правильно указывал использованную модель.

## Проверка качества и диагностика

Промпт получает исходный номер первой реплики человека-оператора; слова клиента, бота и системы не приписываются ему. Применимость N/A проверяется до оценки действия. Для изменённого чек-листа приоритет имеют его правила.

Gemini возвращает компактный объект по responseJsonSchema: ID критериев обязательны, значения типизированы, ссылки ограничены длиной транскрипта. Поля v/r/e разворачиваются сервером в стандартные value/rationale/evidence_turns. Схема выгрузки JSON 1.0 не меняется. Лимит 16384 токенов включает бюджет рассуждений; один запрос на диалог сохраняется.

В data/diagnostics сохраняются отдельные JSON: HTTP-статус, этап ошибки, тип исключения, finishReason, usageMetadata, время и ответ модели (до 24000 символов). Ключ и заголовки запроса не сохраняются; точное совпадение ключа в ответе скрывается. Эти файлы могут содержать фрагменты диалогов и исключены из Git вместе с data/.

Раскройте «Проверка нескольких диалогов без изменения выгрузки», укажите 1–10 ID через запятую и запустите проверку. Результаты находятся в data/verification.json и не заменяют результаты для сдачи. Это настоящие обращения к Gemini, использующие ключ из поля страницы. После изменения версии промпта продолжение старой оценки запрещено: нужна полная переоценка.

## Остановка и измерение времени

«Остановить оценку» отменяет ожидающие и активные HTTP-запросы, сохраняет готовые результаты. Уже отправленный запрос может учитываться провайдером даже после отмены. «Продолжить» обрабатывает недостающие и ошибочные диалоги. Таймер показывает всё время запуска, включая очередь и паузы API. Итог сохраняется в data/runs/*.json и state.last_run. При продолжении отдельно фиксируется количество обработанных за этот запуск.

Один запрос содержит один диалог. Между стартами выдерживается 60/14 + 0.02 секунды (примерно 4.306 секунды); одновременно в обработке не более пяти задач. Скользящее минутное окно учитывает общий RPM. На реальном тесте провайдер сообщил для текущего проекта Free Tier квоту 15 RPM. Квота провайдера сохранена в data/config.json:model_rate_limits. Рабочий предел — 14 RPM с запасом; автоматически уточняется по структурированному QuotaFailure. История резервирования запросов и пауз сохраняется в data/rate_history.json и восстанавливается после перезапуска. С такой квотой 65 отдельных запросов не могут завершиться за 40–50 секунд. Плановая длительность с плавной очередью — около 4.5–5 минут, если нет внешних ошибок и запросов из других приложений того же проекта. Увеличивать число параллельных задач сверх пяти или скрывать паузы в таймере бессмысленно.

## Плеер звонков

Ссылка audio_url организаторов может вести на HTML-страницу, а не на аудиофайл. Сервер извлекает media source из страницы без выполнения её скриптов и сохраняет запись в data/media. Браузер получает медиа через /api/media/{conversation_id}; поддерживаются HTTP Range / 206 для перемотки. Допустимы только HTTPS-адреса организаторов и известный Dynamics-хост, включая проверку перенаправлений. Медиа-кэш исключён из Git. Исходная ссылка остаётся доступной в карточке звонка.

Паузы определяются только по событиям записи, а не по удержанию клиента: удержание само по себе не означает остановку записи. Масштабирование всего звонка под длительность файла не применяется. Если метка всё ещё выходит за пределы аудио, интерфейс показывает сообщение вместо скрытого перехода в конец. Остаточная точность зависит от исходных меток провайдера; это не распознавание и выравнивание речи по аудио.

## Качество и ограничения

Версия grounded-v8 сначала запрашивает e/r, затем v; в конце запроса повторены первая реплика оператора и последние шесть реплик с исходными номерами. Расширенное рассуждение заменяет minimal, который пропускал явные факты даже после уточнения промпта. Версия уточняет: discovery=null только при достаточных исходных данных; обязательное выяснение существенных деталей исключает N/A. Идентификация личности сама по себе не discovery. Представление оператора с [Имя скрыто] засчитывается. Closure требует итог/предложение помощи плюс прощание; реплика клиента «получилось» и инструкция в середине консультации не подменяют завершение оператора. Разрыв до возможности завершить — N/A; обычное отключение после прощания не является обрывом автоматически.

Оценки не подставляются по ID, реальные новые диалоги проходят через модель. Обоснования модели остаются вероятностными: проход JSON-валидации не доказывает семантическую точность или совпадение с Ground Truth. Для контроля запускайте `python -m unittest test_regressions -v`, затем реальные проверки пограничных случаев.

Карточка критерия показывает взвешенные баллы до перераспределения N/A и нормированный вклад в 100-балльный итог. Например, dialogue=7/10 при весе 15 даёт 10.5 балла; вклад в итог равен 100*10.5/сумма применимых весов. Критический флаг не входит в сумму.

## Стоимость

Используемый ключ работает с бесплатной квотой: денежная стоимость вызовов в рамках этого тарифа — 0; ограничение скорости сохраняется. Платный тариф не подключался. Для платного режима стоимость вычисляется по usageMetadata: входные токены/1e6 * актуальная цена входа + выходные токены/1e6 * актуальная цена выхода (с учётом правил тарификации thinking/caching провайдера). Цены другой модели использовать нельзя; фиксированная платная смета без выбранного тарифа не заявляется.

## Сценарий защиты — 5 минут

- 0:00–0:40: FreeDoom / Veritas, загрузка JSON или API, RU/KZ/EN и разделение bot/operator.
- 0:40–1:25: выбранный готовый диалог, доказательства, исходное время и аудио; один настоящий запрос через «Оценить выбранный».
- 1:25–2:10: восемь критериев, rationale, взвешенные баллы, N/A и отдельный критический флаг.
- 2:10–3:10: оператор открывает апелляцию; супервизор принимает решение, итог пересчитывается, original_ai сохранён. Для реальной демонстрации используйте отдельный тестовый набор, не изменяйте сдаваемый DEV.
- 3:10–3:50: редактор правил, веса и шкалы; объяснить, что изменения требуют переоценки.
- 3:50–4:30: очередь 14 RPM, пять задач, остановка/продолжение, диагностика ошибок; полный DEV показывается заранее рассчитанным, потому что сам запуск занимает около 4.5–5 минут.
- 4:30–5:00: JSON 1.0, team_name=Veritas, пути DEV/PROD и публичный репозиторий. Не заявлять готовый PROD до получения контрольного набора.

Стандартные правила contact/closure дополнительно проверяются по однозначным данным: приветствие на указанном языке + анонимизированное имя оператора; отключение клиента перед последней репликой оператора без предшествующего прощания. Для изменённых правил проверки отключены. Исходный ответ Gemini хранится в raw_model_criteria, журнал поправок — evidence_guards (внутренние поля, не включаются в JSON сдачи). Это прозрачная гибридная оценка, а не подстановка результатов по ID.

Дополнительная узкая проверка discovery: запрос «где найти/скачать» с инструкциями по меню, без вопросов оператора и без признаков нерешённой проблемы — N/A. Выбор валюты самим клиентом в интерфейсе не считается уточняющим вопросом оператора. Эта проверка также отключается для пользовательского чек-листа и сохраняет аудит поправок.

Потолок вывода повышен до 16384: это максимум, а не целевой объём обоснований. При high thinking лимит 4096 иногда обрывал JSON (MAX_TOKENS), так как учитывал и скрытое рассуждение. Обоснования по-прежнему обычно 8–18 слов. Успешные ответы не запрашиваются повторно; ошибки повторяются отдельным запуском.

Суточный лимит отличается от RPM: при QuotaFailure с PerDay очередь останавливается, готовые результаты сохраняются, новые запуски отклоняются до сообщённого провайдером сброса. Это не исправляется уменьшением числа потоков. В последней проверке API подтвердил 500 запросов/сутки.

Сдаваемый results.json заменяется атомарно только после полного успешного набора текущей версии. Частичный запуск, отмена и ошибки сохраняются в data/state.json, но не затирают последнюю полную выгрузку. Последняя полная DEV-выгрузка сейчас относится к старому промпту: полная проверка grounded-v8 не завершена из-за суточной квоты; её нельзя выдавать за новый подтверждённый результат.

Проверка 8 ноября: 34 успешных результата grounded-v8, 5 ошибок (3 MAX_TOKENS, 1 HTTP 503, 1 суточный 429), остальные 26 ещё не обработаны. Этот запуск не является завершённым замером производительности. Максимум вывода после этого повышен с 4096 до 16384; реальная проверка нового потолка ждёт сброса квоты. Успешная новая одиночная оценка также проверена только офлайн; в браузере подтверждён безопасный отказ по суточной квоте. Сценарий защиты подготовлен, полный пяти­минутный живой прогон с API ещё не завершён.

Локальные ограничения хранятся отдельно по SHA-256 отпечатку ключа и модели в data/rate_profiles; сами ключи там не сохраняются. Новый ключ не наследует локальную блокировку прежнего, возврат к прежнему восстанавливает его паузу. Квота провайдера может быть общей для ключей одного Google-проекта: в этом случае новый ответ 429 корректно установит ограничение и для нового ключа. Старый файл rate_history.json без привязки к ключу больше не применяется.

По запросу пользователя thinking переключён с high на medium. Промпт и проверки фактов сохранены; новые вызовы используют medium, существующие успешные оценки не пересчитываются. В диагностике каждого вызова записан использованный уровень. Потолок 16384 оставлен для защиты JSON от обрыва; это не обязательный расход токенов.

Текущая настройка по запросу пользователя: thinking low. Промпт, проверки фактов и готовые результаты сохранены.

Сетевое ожидание: connect 20s, read 180s, write/pool 30s. В диагностике queue_seconds и request_seconds разделяют очередь и запрос. Можно скачать текущий JSON при ошибках и во время обработки: такой снимок называется results-incomplete.json и не объявляется готовым к сдаче. Сохранение готовых результатов при повторе ошибок не меняется.

## Уточнение завершения: closure-v9

Фразы вежливости (You’re welcome, Have a good day, Take care, Пожалуйста, Хорошего дня, Сау болыңыз) засчитываются только как прощание, но не как итог или помощь. Предложение помощи требует прямого вопроса о дальнейших действиях; «обращайтесь» само по себе не подходит. Для closure=true нужны прощание и конкретный итог либо прямой вопрос о дальнейшей помощи. Одно «You’re welcome. Have a good day!» — false. Обоснование и ссылки должны подтверждать реально сказанное оператором. Правило N/A при обрыве сохраняется. Существующие оценки автоматически не изменялись: для применения новой версии нужна переоценка.
