# DataDoom — простой прототип

Один server.py, один static/index.html, четыре API-маршрута.
Состояние в словаре Python и локальных JSON; без базы, очереди и аккаунтов.
Запускайте локально одним процессом. Для оценки нужен интернет.

## Запуск на Windows

Установите Python 3.11+ и Git. В папке проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Используется модель `gemini-2.0-flash`. API-ключ вводится прямо на сайте.
Поле ключа изначально пустое, ввод скрыт. Ключ передаётся серверу
только при запуске оценки и затем используется для запроса в Gemini.
Ключ не записывается в JSON, экспорт или хранилище браузера.

```powershell
.\.venv\Scripts\python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Не используйте --workers больше 1.
Не перезапускайте сервер во время обработки.

## Сценарий

1. Введите API-ключ. Выберите DEV/PROD и загрузите JSON с ПК или через GET.
2. При необходимости отредактируйте чек-лист.
3. Нажмите «Оценить все». Оценка последовательная, запросы асинхронные.
4. Прогресс обновляется через GET /api/dialogues. Готовые оценки доступны сразу.
5. После завершения скачайте results.json. Сервер также записывает его
   в results/dev/results.json или results/prod/results.json.
6. Проверьте количество записей и ошибки, сделайте commit + push.

Новый импорт очищает оценки текущего набора. Повторная оценка заменяет их.
Сохранённое состояние восстанавливается из data/state.json после перезапуска.
Если запуск прервался, на диске будет частичный результат: не сдавайте его.
Кнопка скачивания включается только когда есть результат для каждого диалога.
Для PROD требуется 10 записей, DEV — 65. Ошибки тоже включаются в экспорт.

Флаги нарушений имеют kind=flag, вес 0, true/false без N/A.
Баллы считаются кодом, N/A исключается из знаменателя; флаг не обнуляет итог.
Для официальной сдачи используйте исходные восемь критериев и шкалы.
Пользовательские критерии доступны для демонстрации, но их экспорт не
соответствует фиксированным ID организаторов.

## API

- POST /api/load-data
  JSON {"group_id":"DEV"} — GET по ORGANIZER_API_URL (константа в server.py) с нужным group_id.
  JSON {"group_id":"DEV","dataset":{...}} — импорт объекта.
  multipart/form-data: file, group_id — импорт файла.
  Поддерживает data.records, records и массив диалогов.
- GET /api/dialogues — диалоги, результаты, прогресс и объект экспорта.
- POST /api/evaluate с JSON {"api_key":"..."} — оценка всего набора, возвращает итоговый JSON.
  Это и есть пакетная оценка; отдельного /api/evaluate-batch нет.
- POST /api/checklist
  {} — прочитать; {"checklist":[...]} — сохранить.

GET / — отдаёт интерфейс, не дополнительный API-маршрут.
Ключ вводится пользователем на сайте и используется сервером только для текущей оценки. API вызывается через httpx,
поэтому дополнительный SDK не требуется.

## Git

Работайте в main. Если это новый локальный проект:

```powershell
git init -b main
git add .
git commit -m "Add minimal DataDoom app"
```

Добавьте адрес своего репозитория как origin, затем git push -u origin main.
data/ исключён, results/ включён в Git.

## Ограничения этой минимальной версии

Апелляции не входят в эти четыре маршрута и пока не реализованы.
Это упрощённый этап разработки, не вся функциональность исходного ТЗ.
Длинный POST может прерваться на прокси хостинга; локальный запуск предпочтителен.
Без постоянного хранилища на Render JSON-файлы могут пропасть при перезапуске.
База данных для этого прототипа не требуется.

Реальный запрос Gemini требует вашего ключа и доступной модели.
Стоимость оценки и её точность измерьте на DEV и внесите сюда перед сдачей.
